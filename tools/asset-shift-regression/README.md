# 위치 어긋남 검사 회귀 테스트

웹툰앱 동영상형 검수의 **위치 어긋남 검사**(`src/assetShiftCheck.mjs`)가
파라미터를 바꾼 뒤에도 같은 판정을 내는지 확인하는 도구입니다.

## 왜 필요한가

이 검사는 임계값 4개(`MIN_SHIFT`, `ERR_RATIO`, `FLAT_STD`, `MIN_CONSENSUS`)로 판정이 갈립니다.
하나를 조금만 조여도 **정상 소재를 불일치라고 하는 오탐**이 생기고,
조금만 풀면 **실제 밀림을 놓치는 미탐**이 생깁니다.
두 방향을 동시에 확인해야 하므로, 정상 소재와 불일치 소재를 한 세트로 묶어 돌립니다.

## 사용법

소재는 광고 소재라 저장소에 커밋하지 않습니다. 스틸컷·영상 원본에서 매번 생성합니다.

```bash
cd tools/asset-shift-regression

# 1) 소재 세트 생성 (pillow, numpy, ffmpeg 필요)
python3 make-fixtures.py <스틸컷.jpg> [영상.mp4]

# 2) 회귀 테스트 실행
node run.mjs
```

영상 인자는 생략 가능합니다. 넣으면 실제 반입 소재가 `real` 케이스로, 그리고
영상 첫 프레임을 JPEG 로 내보낸 **실제 조건 정상 쌍**(`ok-real-q95`/`q85`)이 추가됩니다.
스틸컷의 카피라이트 띠 위치가 다른 소재라면 `--band y0,y1` 로 지정하세요 (기본 `515,580`).

### 다른 소재를 추가할 때

카피라이트 띠가 없어 합성 밀림 케이스가 의미 없는 소재는 `--pair-only` 로
실제 쌍과 정상 쌍만 만듭니다. 고양이 소재(얇은 텍스트 추가) 예시:

```bash
python3 make-fixtures.py <고양이_스틸컷.jpg> <고양이_영상.mp4> \
  --pair-only -o fixtures-cat \
  --real-expect known-gap --real-edge review \
  --real-note '실제 반입 소재 — 얇은 텍스트 추가'

node run.mjs fixtures-cat
```

`--real-expect` 는 위치 검사, `--real-edge` 는 윤곽선 검사 기대값입니다
(`quiet` 조용해야 함 / `review` 확인필요가 떠야 함 / `any` 채점 제외).

## 케이스 구성

생성기는 스틸컷 1장에서 아래 17종을 만듭니다.
정상 케이스는 스틸컷을 H.264로 인코딩한 뒤 첫 프레임을 다시 뽑아,
**실제 반입 소재와 같은 경로(정지 이미지 → 코덱 → 디코딩)** 를 재현합니다.

| 케이스 | 기대 | 확인하는 것 |
|---|---|---|
| `real` | 어긋남 | 실제 반입 소재 (카피라이트 10px 밀림) |
| `ok-real-q95`·`q85` | 정상 | **실제 조건 정상 쌍** — 영상 첫 프레임의 JPEG 판. 윤곽선 검사 기준을 잡는 근거 |
| `ok-clean` | 정상 | 기본 인코딩 노이즈 내성 (실제 대비 2.8배 과압축) |
| `ok-lowbitrate` | 정상 | 압축 노이즈 내성 (실제 대비 6.4배 과압축) |
| `ok-soft` | 정상 | 절반 축소 후 재확대(리스케일 흐림) 내성 |
| `diag1` | 어긋남 | **전체 대각선 1px 밀림** — `MIN_SHIFT=2` 로는 놓쳤던 케이스 |
| `shift2`~`shift10` | 어긋남 | 2px부터 검출 |
| `shiftx12` | 어긋남 | 좌우 방향 밀림 |
| `whole10` | 어긋남 | 이미지 전체 밀림 |
| `shift1` | 알려진 한계 | 좁은 영역만 1px 밀림 — 오차감소비 0.70 으로 임계 미달 |
| `gap-missing` | 알려진 한계 | 카피라이트 삭제 — 위치 검사로는 검출 불가, **윤곽선 검사가 '확인필요'로 올림** |

`ok-lowbitrate`·`ok-soft`는 **실제 반입 소재보다 노이즈가 훨씬 심합니다**
(고디테일 블록 잔차: 실제 3.1 vs 저비트레이트 34.3).
현실보다 가혹한 조건이라, 여기서 오탐이 없으면 실제 운영에서는 더 안전합니다.

### 알려진 한계 두 건 — 자동 검사로 못 잡는 영역

두 케이스는 **"검출 못 하는 것이 현재 정상"** 으로 채점합니다.
검출되기 시작하면 한계가 해소된 것이니 문서를 갱신하세요.

**`gap-missing` — 요소 누락·추가·교체**
평행이동이 아니라 있다·없다의 문제라, 밀어봐도 맞는 자리가 없어 위치 검사로는 구조적으로
잡히지 않습니다. 큰 차이(다른 이미지·타이틀, 영상 후반 프레임 오인)는 색차 검사가 담당하지만
얇은 텍스트 한 줄 같은 작은 요소는 두 검사 모두 통과합니다.

여기까지는 그대로지만, **윤곽선 검사가 이 케이스를 '확인필요'로 올립니다**(아래 참조).
반려는 아니고 육안 확인을 안내하는 단계라, 예전처럼 '일치'로 조용히 넘어가지 않습니다.
러너의 채점은 위치 검사 기준이라 여전히 `known-gap` 입니다.

**`shift1` — 좁은 영역만 1px 밀림**
`MIN_SHIFT` 를 0으로 낮춰 1px 밀림도 후보로 삼지만, 좁은 영역의 1px 은 압축 노이즈에 묻혀
오차가 충분히 줄지 않습니다(오차감소비 0.70, 임계 0.6). `ERR_RATIO` 를 0.75 로 올리면
잡히지만 정상 소재 최악값이 0.85 라 여유가 없어 두지 않았습니다.
반면 **전체가** 1px 밀린 경우(`diag1`)는 블록이 많아 합의가 쉬워 정상 검출됩니다.

이 두 구멍은 검수툴의 **겹쳐보기·깜빡임 육안 비교**와 윤곽선 검사의 **확인 권장 지점**
안내가 메웁니다. 깜빡임 모드는 1px 밀림도 육안으로 바로 보입니다.

## 판정 기준을 바꿀 때

1. `src/assetShiftCheck.mjs` 의 `ASSET_SHIFT_PARAMS` 를 수정
2. `node run.mjs` 와 `node run.mjs fixtures-cat` 전부 통과 확인
3. 실패한 케이스가 있으면 **그 파라미터는 쓰지 않습니다**

### 시도했으나 폐기한 최적화 (다시 넣지 마세요)

전수 탐색 대신 "소재 노이즈 중위값 대비 튀는 블록만 탐색"하는 사전 선별을 넣으면
검사 시간이 550ms → 15ms로 줄지만, `shift3`·`shift4`·`whole10` 을 **모두 놓칩니다**.
노이즈가 심한 소재에서는 선별 기준선이 너무 높아지고,
이미지 전체가 밀린 경우에는 중위값 자체가 올라가 모든 블록이 걸러지기 때문입니다.

현재 코드는 전수 탐색을 유지한 채, 결과가 바뀌지 않는 **조기 중단**(누적 오차가 현재 최소값을
넘는 순간 중단)만 적용해 1,430ms → 550ms로 줄였습니다.

## 윤곽선 검사 (`src/edgeDiffCheck.mjs`) — '확인필요' 판정

색차·위치 검사가 모두 놓치는 **요소 추가·삭제**를 짚어냅니다.
**반려 판정에는 넣지 않고 '확인필요'까지만** 올립니다.

| 판정 | 조건 | 의미 |
|---|---|---|
| 불일치 | 색차 **또는** 위치 검사 불일치 | 자동 반려 대상 |
| 확인필요 | 윤곽선 검사만 불일치 | 검수자 육안 확인 |
| 일치 | 셋 다 통과 | — |

### 방식 — 지역별 윤곽선 '밀도' 비교

32px 창을 16px 간격으로 훑으며 창 안의 윤곽선 픽셀 수를 양쪽에서 세고,
`적은 쪽 / 많은 쪽` 비율이 `RATIO`(0.30) 미만인 창을 의심 블록으로 봅니다.
의심 블록이 2개 이상이면 확인필요입니다.

**이전에는 '한쪽에만 있는 윤곽선'을 셌는데, 배경이 복잡한 곳에 얹힌 요소를 놓쳤습니다.**
고양이 소재의 얇은 흰 텍스트가 고양이 털 위에 있어서 텍스트 윤곽선 주변에 털 윤곽선이
양쪽 모두 존재했고, 그래서 '한쪽에만 있는 것'으로 분류되지 않았습니다.
밀도 비교는 배경과 무관하게 "이 자리에 윤곽선이 훨씬 많다/적다"를 보므로 이 경우도 잡습니다.

### 기준값 근거 — 실제 반입 소재로 보정

| 케이스 | 블록 최저 비율 | 판정 |
|---|---|---|
| **고양이 · 얇은 텍스트 추가** | **0.03** | **확인필요 ✔** |
| 고양이 · 정상 (JPEG q95) | 0.89 | 통과 ✔ |
| 고양이 · 정상 (JPEG q85) | 0.89 | 통과 ✔ |
| 블리치 · 정상 (JPEG q95) | 0.96 | 통과 ✔ |
| 블리치 · 정상 (JPEG q85) | 0.87 | 통과 ✔ |

결함 0.03 과 정상 최저 0.87 사이가 넓어 `RATIO` 0.30 을 그 사이에 뒀습니다(약 29배 차이).

**합성 정상 소재(`ok-clean`/`ok-soft`/`ok-lowbitrate`)는 이 검사의 기준 근거로 쓰지 않습니다.**
실제 반입 영상보다 2.8~6.4배 과압축이라 원본의 가는 무늬가 통째로 뭉개져
'요소가 삭제된 것'과 구분되지 않습니다. 이 케이스들은 `edge: "overcompressed"` 로
표시해 윤곽선 채점에서 제외하고, 위치 검사 오탐 확인 용도로만 남겨 둡니다.

### 확인 권장 지점 — 세 검사 모두 표시

겹쳐보기 팝업의 마커는 세 검사 결과를 함께 표시합니다. 불일치가 났는데 화면에 아무 표시가
없으면 어디를 고쳐야 할지 알 수 없기 때문입니다.

| 마커 색 | 검사 |
|---|---|
| 보라 | 위치 어긋남 (해당 영역) |
| 노랑 | 색차 (차이 큰 셀) |
| 주황 | 요소 추가·삭제 의심 |

## 색차 검사 임계 — 셀 ΔE 를 낮추지 않은 이유

셀 ΔE 를 8 → 4 로 낮추자는 제안이 있었으나 실측 후 8로 유지했습니다.
브라우저 영상 디코딩 경로(`<video>` → canvas, ffmpeg 와 결과가 다름) 기준입니다.

| 케이스 | 평균 ΔE | 최대 셀 ΔE |
|---|---|---|
| 정상 기본 인코딩 | 0.109 | 3.526 |
| **정상** 저비트레이트 | 0.176 | **4.039** |
| 정상 리스케일 | 0.104 | 3.526 |
| 결함 10px 밀림 | 0.022 | 1.031 |
| 결함 1px 밀림 | 0.079 | 2.461 |
| 결함 요소 삭제 | 0.064 | 2.838 |

**실제 결함의 최대 셀 ΔE(1.03~2.84)가 정상 소재(4.04)보다 낮습니다.**
어떤 임계값을 써도 이 셀 규칙으로는 결함을 잡을 수 없고, 4로 낮추면 정상 소재가
1셀 초과로 반려됩니다(`STILL_FRAME_MISMATCH_RATIO = 0` 이라 1셀만 넘어도 불일치).
낮출 이득이 없고 오탐 위험만 생기므로 8을 유지했습니다.

평균 ΔE 는 12 → **1.5** 로 조였습니다. 정상 소재 최대 0.176 대비 8.5배 여유가 있고,
'영상 후반 프레임을 스틸컷으로 오인'한 케이스가 2.52 로 검출됩니다. 12는 사실상 작동하지 않았습니다.
